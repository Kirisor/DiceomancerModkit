# 奶蛙卡组 · 强度平衡方法（v2：按定位与乘区定价）

> v1 的「每费分」模型已被推翻，原因见第 0 节。本版按游戏真实的伤害管线重写，
> 并用「定位」把卡分组 —— **跨定位比每费分是没有意义的**，那是 v1 的根本错误。

## 0. v1 错在哪（撤回）

| v1 的做法 | 错在哪 |
|---|---|
| 把伤害 / 易伤 / 虚弱 / 流血 / 坚韧 折成同一个"分"相加 | 四种东西的作用完全不同：伤害是产出，易伤/虚弱是**检定概率**修正，流血是延后结算，坚韧是减伤 |
| 只按「每费分」排序 | 防御卡在后期天然贬值，真伤卡上限锁死，引擎卡的价值体现在"顺序/组合"上，三者不能同尺 |
| 完全没有「段数 × 乘区」 | 本作 flat 加值（力量、脆皮）**按段结算**，段数越多吃得越多 ⇒ 多段卡被严重低估 |
| 把「蛙群瞪视」的连锁部分当成 8 点群体伤害 | **事实错误**：`mf_glare_cascade` 施加的是 **易伤**（`Vulnerable`），不是伤害 |

## 1. 本作的伤害管线（权威来源：游戏本地化文本）

检定规则：**扔 d20，结果 ≥ 需求值即成功**；层数加到结果或需求上。

| 能力/关键词 | 中文 | 机制 | 影响 |
|---|---|---|---|
| `Power` | 力量 | 攻击伤害增加 X | **每段加算**（flat） |
| `ThinSkin` | 脆皮 | 受到攻击时伤害增加 X，回合开始减半 | **每段加算**（flat，对目标） |
| `CriticalHit` | 暴击 | 攻击时检定（+暴击层数），成功伤害翻倍 | 乘算 ×2 |
| `Vulnerable` | 易伤 | 受击时检定（+易伤层数），**失败**则伤害翻倍；回合开始减半 | 乘算 ×2 |
| `Weak` | 虚弱 | 攻击时检定（+虚弱层数），**失败**则伤害减半；回合结束减半 | 乘算 ×0.5 |
| `Tough` | 坚韧 | 受击时失去一半并检定（+坚韧层数），成功伤害减半 | 乘算 ×0.5 |
| `Evade` | 闪避 | 受击时检定（+闪避层数），成功则不命中 | 归零 |
| `Kick` / `Amplification` | 增幅 | 下次骰子结果 +N，结算后减半 | **检定成功率货币**，不是伤害数字 |
| `Bleed` | 流血 | 回合结束时失去 X 生命，然后层数减半 | 延后、可叠、不吃乘区 |
| `DicePenalty` | 倒霉 | 投骰时多投一颗取最小；每 N 层再多家一颗 | 摧毁敌方所有检定 |
| 真伤（`lose_life`） | — | 直接扣血 | **不进上面这条管线**：不吃力量、不吃暴击/易伤、不吃脆皮 |

**由此得到两条硬结论：**

1. **段数是主乘区**。单段 `(base + 力量) + 脆皮` 只吃一次 flat；两段吃两次。
   举例（3 力量 + 3 脆皮 + 易伤成功 + 暴击成功）：
   - 单段 6：`((6+3)×2 + 3) × 2 = 42`
   - 两段 3：`((3+3)×2 + 3) × 2 × 2 = 60` ← **142.8%**
   ⇒ 任何"提高段数"的东西（连锁条数、多段效果）价值远高于同等白值。
2. **真伤是反乘区**。它的上限在拿到那一刻就定死了，随敌人成长贬值；
   要么给更高白值，要么给它"独占优势"（无视护甲/无视检定/无视减伤）。

## 2. 五种定位（这才是分组标准）

| 定位 | 价值来源 | 验收标准 |
|---|---|---|
| **carry** | 段数 × 乘区 × 白值 | 后期单回合能打出多少"段×期望伤害" |
| **乘区供给** | 让 carry 的每一段 ×2 或 +N | 拐到主 carry 后的**增量**，不看自身输出 |
| **段数供给** | 提供额外结算实例（连锁条数、召唤、多段） | 每点能量换来多少段 |
| **防御** | 多活几回合 | 能否撑到组合成型；后期按"敌人白值×0.5 是否够用"判 |
| **引擎** | 改变顺序/概率/资源 | 组合上界（例：结算顺序、增幅、能量） |

当前 19 张的归属（按实际数据，非方案稿）：

| 定位 | 卡 |
|---|---|
| carry | 蛙群怒涛（6 群体 + 连锁 2 条）、托奶斯回旋（4 + 增幅 2 + 连锁 1）、蛙群瞪视（4 群体直伤部分） |
| 乘区供给 | 蛙群瞪视（被连锁 → 全体易伤 8）、愤怒的奶蛙（临时力量 3，被连锁再给力量 2）、奶蛙大笑（闪避属防御向乘区） |
| 段数供给 | 大胃袋（0 费 + 连锁 2，白送两段）、托奶斯回旋（连锁 1 + 增幅） |
| 防御 | 衰奶蛙（虚弱 8 + 倒霉 8 + 流血 8）、大胃袋（坚韧 3 及其滚雪球）、豆奶之吻（流血 8 群体）、奶蛙格挡（3 格挡） |
| 真伤 | 胞兄之恨（失血 6 + 被连锁流血 5） |
| 引擎 | 以母之名（**干预奶蛙结算顺序**）、奶蛙思考（检索/能量/抽牌）、寻找黄色生物（能量/构思）、奶蛙回旋（弃牌堆转化） |

## 3. 逐卡的正确读法（修正后的判断）

- **衰奶蛙**：虚弱 8 + 倒霉 8 + 流血 8，是**纯生存**。后期敌人白值一高，减半后仍然疼，
  而且它不推进击杀 ⇒ 只有被连锁带出来时才划算。**不是超模，是"定位正确但强度偏低"**。
- **蛙群瞪视**：4 点群体直伤 + 被连锁时全体易伤 8。它是 **carry 的拐**：
  没有高白值 carry，易伤层数再多也只是"翻一倍零头"。**不该按伤害给它定价。**
- **大胃袋**：坚韧只减半，且叠再多也不产生输出 —— "叠最厚的甲挨最疼的打"。
  它真正的价值是 **0 费、连锁 2 条**：白送两个结算实例，还是防御向段数。
- **胞兄之恨**：伤害全是真伤 ⇒ **吃不到力量/脆皮/暴击/易伤任何乘区**，上限锁定。
  在乘区堆叠的卡组里它是贬值资产。
- **愤怒的奶蛙**：临时力量 3（被连锁再 +2 力量）—— 与瞪视同属**直伤组件的拐**，
  两者叠加才有一波爆发；单独拿出来看它"没有输出"是误读。
- **蛙群怒涛 / 托奶斯回旋**：**被 v1 严重低估**。前者 = 被连锁时的额外收益 + 2 段，
  后者 = 主动触发奶蛙的引擎（增幅 2 提高检定成功率）。实机通关局都拿了这两张 ——
  这就是"段数 + 增幅"在本作强势的直接证据。
- **以母之名**：3 费买的不是伤害，是**结算顺序**。愤怒的奶蛙先结算还是后结算、
  拉出来的是生存卡还是攻击核心，结果完全不同。它是**后期上限卡**，
  定位应当是"boss 奖励"，而不是躺在普通奖励池里跟奶蛙打击同概率。

## 4. 真正需要动的地方（按可操作性）

1. **以母之名的获取途径**（平台缺陷，最该改）：现在 16 张池卡全部塞进 `commonCards`，
   稀有度零生效 ⇒ Rare 的以母之名和 Common 的打击同概率。
   改法：`CareerAssembler` 按 `CardSo.rarity` 分流到 common / unCommon / rare 三个数组，
   让它只在 boss/精英奖励里出现。

   > **2026-10-24 复核后作废**：稀有度其实是生效的（rarity 写进 `CardInfo.rarity`，
   > 掉落由每个包的 `acceptedCardRarity` 白名单过滤，三档数组与掉落无关）。
   > 用户决定：**实测能正常掉落就不改**，本项只保留为"若小怪也掉以母之名"时的备选方案。
2. **真伤卡的补偿**：既然不吃乘区，就给"独占优势"（无视护甲/无视坚韧检定），
   否则它永远是连锁燃料。
3. **0 费段数供给**（大胃袋）：要控强度就动它的 `milk_frog 2`（段数），
   不要动坚韧数值 —— 动防御数值只会让它"更没人带"。
4. **防御卡的过渡期职责**：如果连前期都没人愿意带，说明它连"活着进入中期"都做不到；
   这类卡应该提高的是**效率**（更低费 / 更高层数 / 被连锁时额外收益），而不是伤害。

## 5. 平衡流程（改后）

1. 先按实机通关数据定 **carry 榜**（哪些卡真的把人送过终点）；
2. carry 只允许动三样：白值、段数、增幅 —— 一次动一个；
3. 乘区供给卡看"给 carry 的增量"，不看自身；
4. 防御卡用"多活几回合"验收；
5. 引擎卡（以母之名）用"获取途径"控制频率，而不是削数值。

> 已知限制：原版卡的数字无法自动导出（在 Unity asset 序列化里，`ModKitDump` 只给
> `EffectName/目标/条数`），所以任何绝对值都要靠实机校准；本文的机制描述取自
> 游戏本地化文本（`ModKitDump/localization-zh.json`），可直接引用。
